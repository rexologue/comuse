# Свои команды

Кроме встроенных команд из `internal_tools/` у агента бывают свои: их добавляет
пользователь (свой скрипт) или пишет чат. Имя у них такое же, как у встроенных,
`группа.действие` (`telegram.send`), но группа своя: во встроенную (`mail`, `fs`…) своя
команда не попадает. В каталоге (`GET /tools`) они стоят рядом со встроенными с
`"source": "external"` и хешем кода (`code_hash`), и агент с компилятором пользуются ими
так же: свою команду отличает `source`, а не имя. Задача помнит определение каждой
команды, с которым её одобрили, — своей и встроенной одинаково ([TASKS.md](TASKS.md#команды-задачи)).
Код — `common/external_tools/`, API и таблица — у executor.

## Код команды

Версий у команды нет: есть одобренный код (`current`, его вызывают) и, может быть,
черновик (`draft`). Каждый — своя папка:

```
DATA_DIR/external_tools/<группа>/<действие>/{current,draft}/
  tool.json           манифест
  main.py             def run(args, ctx)
  …                   другие .py и небольшие файлы данных (.json, .txt, .csv, .md, .yaml)
  requirements.txt    пакеты, которые команда объявила
  requirements.lock   точные версии всех пакетов с хешами
  .venv/              своё окружение
```

Имя — латиница в нижнем регистре, цифры и `_` (`parse_invoice`). Хеш кода считается по
всем файлам, кроме `.venv`, и хранится в базе.

### tool.json

```json
{
  "title": "Разобрать дату",
  "description": "Переводит дату в свободной форме в ISO 8601",
  "card": "Разобрать дату «{text}»",
  "confirm": false,
  "timeout": 60,
  "input_schema": {"type": "object", "properties": {"text": {"type": "string"}}, "required": ["text"]},
  "output_schema": {"type": "object", "properties": {"iso": {"type": "string"}}, "required": ["iso"]}
}
```

| Поле | Что это |
| --- | --- |
| `title`, `description` | Название и описание: по описанию модель выбирает команду |
| `card` | Что видит пользователь перед вызовом, с `{аргумент}`; пусто — `title` |
| `confirm` | Как у встроенных: `true` — спросить, `"always"` — каждый раз, `false` — не спрашивать |
| `timeout` | Секунды; пусто — `tool_timeout_sec`. Установка пакетов при первом вызове в это время не входит |
| `input_schema`, `output_schema` | JSON Schema объекта. Аргумент с `"x-path": "path"` (у списка — в `items`) — путь в рабочей папке: executor проверяет его до вызова и передаёт команде полным путём |

### main.py

```python
from agent_tool import ToolError   # необязательно: ошибка для пользователя без traceback


def run(args, ctx):
    ...
    out = ctx.output_path("итог.txt")    # файл в результатах запуска, станет артефактом
    ctx.log("строк: 3")                  # строка в журнал запуска или трассу чата
    return {"iso": "...", "file": str(out)}
```

`ctx`: `mode` (`chat` / `run`), `dry_run`, `output_dir`, `log(text)`,
`output_path(filename)`. Ответ — JSON-объект по `output_schema`; полные пути в нём
executor переводит обратно в пути вида `Отчёты/x.xlsx` / `data:outputs/…`. Что команда
печатает, попадает в журнал и ответ не ломает.

Аккаунтов и LLM у своих команд нет: это детерминированные функции. Модель, почта —
соседние шаги `llm.*`, `mail.*` в задаче.

## Пакеты

Пакеты ставит uv (зависимость проекта, поэтому он есть везде, где стоит агент):

1. при сохранении черновика `requirements.txt` разрешается в `requirements.lock`:
   точные версии всех пакетов, включая транзитивные, с хешами. Этот список видит тот,
   кто одобряет черновик;
2. при одобрении — заново, с пустой папки (что оставил в `.venv` пробный запуск
   черновика, в одобренный код не попадает), а при первом вызове, если `.venv` пропал, —
   `uv venv` на интерпретаторе агента и `uv pip sync --require-hashes --only-binary :all:`.

В `requirements` — по одному пакету из индекса в строке: строки с переводом строки,
опциями (`-r`, `-e`, `-c`…), путями и URL отклоняются.

Ставятся только готовые wheel-пакеты: при установке wheel код пакета не выполняется, при
сборке из исходников выполнялся бы. Пакета без wheel под эту платформу не поставить —
ошибка это скажет. Кеш uv — `DATA_DIR/cache/uv`: одинаковые пакеты в разных командах и
черновиках ставятся почти мгновенно и почти не занимают места. Индекс пакетов — PyPI или зеркало из
`UV_INDEX_URL`; без сети работают только команды без пакетов.

Наших библиотек в `.venv` команды нет: что ей нужно, она объявляет сама.

## Жизнь черновика

```
черновик ──одобрил человек──▶ одобренный код (прежний удалён)
   │
   └──выбросили──▶ удалён
```

- **Черновик** у команды один. Его можно сохранять сколько угодно раз: папка
  переписывается (`.venv` переиспользуется). При каждом сохранении проверяются
  имя, манифест, файлы (только внутри папки, разрешённые расширения, размер), что `.py`
  компилируется и что пакеты разрешаются (это делается в отдельной папке до записи
  файлов). Все несовпадения — одной ошибкой, и тогда ничего не записано. `__pycache__` в
  файлах команды нельзя. Чат не заменяет черновик, который написал человек или другой чат.
  Запись, удаление и одобрение черновика одной команды идут по очереди.
- **Одобряет только человек**, прочитав код и список пакетов. Одобрение называет хеш
  черновика, который человек видел: если чат переписал черновик, пока карточка была
  открыта, одобрение отклоняется и карточка показывает новый код. Если файлы черновика
  изменились после сохранения, одобрение тоже отклоняется. После одобрения папка
  черновика становится `current` (прежний код удаляется), заново ставятся пакеты,
  каталог executor обновляется (agent-loop видит новую команду в течение минуты).
- **Одобренный код не меняется.** Перед каждым вызовом executor сверяет файлы с
  хешем (всё, кроме `.venv`, в том числе `__pycache__`); не совпало — команда не
  запускается.
- **Задачи с командой ждут решения.** Новый код — другое определение команды, поэтому
  задачи, которые её вызывают, не запускаются, пока пользователь не посмотрит изменения
  и не одобрит каждую с новым кодом ([TASKS.md](TASKS.md#команды-задачи)). Чат вызывает
  новый код сразу.

## В интерфейсе

«Настройки» → «Команды»: свои команды — одобренный код и черновик, пакеты, задачи с
командой; одобрить или выбросить черновик; «Править черновик» и «Черновик на основе
этого кода»; «Добавить команду» — свой скрипт: название, описание, схемы, `main.py`, пакеты.
Всё сохраняется черновиком и начинает работать после одобрения.

## Из чата

Агент пишет команду сам, командами группы `tools` (только в чате):

1. `tools.list` — нет ли уже такой; доработать — сначала `tools.show` (код и пакеты);
2. `tools.draft` — сохранить черновик: название, описание, схемы, файлы, пакеты. Ничего не
   запускается; ошибки проверки приходят все сразу, агент исправляет и сохраняет снова
   (тот же черновик). Черновик запоминает чат (`created_by: chat`, `session_id`);
3. `tools.try` — запустить черновик на настоящем файле пользователя. Спрашивает «да»
   каждый раз: код не одобрен. При первом запуске ставятся пакеты;
4. агент говорит, что черновик готов. В этом чате появляется карточка: описание, пакеты,
   код, «Одобрить» и «Выбросить». Одобрить может только человек.

После одобрения команда в каталоге (агент видит её в течение минуты), и из того же чата
можно собрать задачу, которая её использует.

## Вызов

Команда работает в отдельном процессе: python из её `.venv` запускает
`common/external_tools/shim.py`, тот получает `{"args", "context"}` на stdin, вызывает
`run` и отвечает JSON на stdout. Процесс получает очищенное окружение (без токенов,
ключей и прокси агента), флаги `-I -B -X utf8`, рабочую папку результатов и свою группу
процессов. По тайм-ауту, а также если ответ больше 20 МБ, убивают всю группу, вместе с
процессами, которые команда запустила. Из того, что команда печатает, хранится только
последняя часть. Ответ проверяется по `output_schema`.

Это не песочница: код может прочитать то, что может пользователь, и выйти в сеть.
Безопасной команду делает человек, который прочитал и одобрил её код.

## API

Через main, с токеном внешнего API.

| Маршрут | Что делает |
| --- | --- |
| `GET /external-tools` | Команды: `current` и `draft` каждой (кто и когда записал, хеш; нет — `null`) |
| `GET /external-tools/{name}/current`, `…/draft` | Одобренный код или черновик: манифест, пакеты, хеш, код (`files` — без служебных `tool.json` и `requirements.*`), `requirements` и `entry` — файл с `run` |
| `PUT /external-tools/{name}/draft` | Сохранить черновик: `{"manifest", "files", "requirements"}` |
| `DELETE /external-tools/{name}/draft` | Выбросить черновик |
| `POST /external-tools/{name}/draft/approve {hash}` | Одобрить черновик, который человек видел (`hash` из его вида) |

```json
{
  "manifest": {"title": "Разобрать дату", "description": "…", "input_schema": {…}, "output_schema": {…}},
  "files": {"main.py": "from dateutil import parser\n\ndef run(args, ctx):\n    …"},
  "requirements": ["python-dateutil>=2.8"]
}
```

Ошибки проверки и установки — `400` с текстом, что не так.
