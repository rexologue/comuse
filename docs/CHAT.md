# Чат

Этот документ описывает agent-loop: как ведётся чат, как агент выбирает и вызывает
команды, когда спрашивает пользователя и чем управляет сам.

Чат — это запись работы. Агент делает просьбу через команды и показывает результат,
пользователь поправляет. Из этой записи компилятор потом собирает задачу (см.
[TASKS.md](TASKS.md)), поэтому всё, что в чате происходило, сохраняется: сообщения и
каждый вызов команды с аргументами и результатом.

## Сессии

У каждого чата есть `session_id` (`ses_…`). Он появляется на первом сообщении, задолго
до того, как из чата соберётся задача, и возвращается в каждом ответе.

Агент — OpenAI-совместимый `POST /v1/chat/completions`, и чат он находит так:

1. **`session_id` пришёл** — в поле тела (например, через `extra_body` в OpenAI SDK)
   или в `metadata.session_id`, официальном поле Chat Completions. Неизвестный id — 404.
2. **`session_id` не пришёл, но в `messages` есть прежняя переписка** — так работают
   обычные чат-клиенты вроде Open WebUI: про `session_id` они не знают и каждый раз
   присылают всю переписку. Тогда агент ищет чат, в котором реплики пользователя и
   ответы ассистента с текстом заканчиваются ровно этой перепиской. Системные
   сообщения клиента, вызовы команд и сообщения задач в сравнении не участвуют. Если
   подходят несколько чатов, берётся самый свежий.
3. **Ничего не нашлось** (или это первое сообщение) — начинается новый чат.

Из `messages` агент берёт только последнее сообщение пользователя: история хранится у
него, а не у клиента.

После `task_compile` у задачи появляется ссылка на чат, из которого она собрана
(`source_session_id`). В этот чат приходят сообщения её запусков и в нём же её удобно
править. Любой другой чат — временное место разговора.

**Временные чаты не хранятся.** Чат задачи — тот, из которого задачу собрали или правили
словами (`source_session_id` задачи или `session_id` версии): он живёт, пока жива
задача. Остальные чаты временные:

- agent-loop раз в час удаляет временные чаты, в которых не писали дольше настройки
  `chat_idle_hours` (24 часа по умолчанию, см. [SETTINGS.md](SETTINGS.md)), вместе с
  сообщениями, трейсом и согласиями «больше не спрашивай»;
- удалить сразу — `DELETE /agent/sessions/{id}`; чат задачи так не удаляется (`409`), как и
  чат, где агент ещё работает;
- файлы чата в `data:outputs/<чат>/` уходят позже, по общему сроку хранения;
- в `GET /agent/sessions` у чата задачи есть `task_id`, у временного — `null`.

## Ход

**Один ход на чат.** Пока агент отвечает, следующее сообщение того же чата ждёт конца
хода и только тогда записывается в историю и обрабатывается: два хода никогда не пишут
в одну историю вперемешку. Идёт ли ход, видно по `busy` в `GET /agent/sessions/{id}` —
так клиент и после перезагрузки страницы знает, что агент ещё отвечает.

1. Сообщение пользователя записывается в историю. Длиннее
   [`agent_message_max_chars`](SETTINGS.md) (20 000 символов) — отказ `413` до записи: такое
   сообщение модель не вместила бы, а окно истории держит текущий ход целиком, и чат
   сломался бы насовсем. Длинный текст — файлом в рабочей папке.
2. **Отбор команд.** Модели показываются: топ [`agent_tools_top_k`](SETTINGS.md) (24) команд по
   близости эмбеддингов к сообщению, команды, уже использованные в этом чате, и
   команды с флагом `core` (сейчас `fs.list` и `docs.read`). Короткий ответ («да»,
   «продолжай», короче 80 символов) ранжируется вместе с тем, на что он отвечает:
   последним сообщением ассистента и предыдущим пользователя. Команда, которую модель
   вызвала не из этого отбора, добавляется в отбор хода: следующие её вызовы — уже со
   схемой. Без модели эмбеддингов,
   при недоступном сервере (тогда отбор выключается на 5 минут) или если команд
   меньше лимита модель видит весь каталог. Каталог агент перечитывает у executor раз
   в минуту.
3. **Системный промпт** — правила работы, текущие дата и время с часовым поясом (иначе
   модель выдумывает время, например для имени файла), готовые границы прошлой и
   текущей недели и прошлого месяца (модели плохо считают календарь) и
   инструкции групп тех команд, что показаны на этом ходе (см.
   [TOOLS.md](TOOLS.md#инструкции-группы)).
4. **Цикл.** Модель отвечает текстом или вызывает команды. Каждый вызов исполняется,
   результат идёт в историю, модель вызывается снова. Результат длиннее 6000 символов
   укорачивается по полям: сокращаются самые длинные строки и списки (с пометкой,
   сколько показано из скольких), а все поля остаются — `truncated`, список вложений и
   прочее после длинного текста модель видит. Вызов, который на этом ходе уже не удался
   с теми же аргументами, не повторяется: модель получает «уже не удался: …, не повторяй».
   Ход заканчивается ответом без вызовов или после `agent_max_iterations` (16) шагов;
   тогда модель ещё раз, уже без команд, говорит, что сделано, что нет и почему.
   Пустой ответ без вызовов получает одну просьбу продолжить; при сбое сервера модели
   (502) шаг повторяется, всего до трёх попыток.

**Окно истории.** Модель видит последние `agent_history_messages` (40) сообщений, но
текущий ход — всегда целиком, от сообщения пользователя: длинный ход с десятками
вызовов не должен оставить модель без самой просьбы. Окно никогда не начинается
посреди обмена «вызов → результат». У вызова, ход которого оборвался до ответа, в
истории появляется результат-ошибка «вызов прерван»: без него API отклонял бы все
следующие ходы. Сбой одного вызова тоже становится его результатом, а не концом хода.

**Трейс.** Каждый вызов команды записывается в `trace_events` со статусом: `ok`,
`error`, `needs_approval` (ждёт ответа пользователя), `confirmed` (выполнен после
согласия). Вызовы мета-инструментов записываются с префиксом `meta:`. В
`GET /agent/sessions/{id}` у записи трейса есть `message_id` — сообщение ассистента,
в котором модель вызвала команду.

## Вопрос перед действием

Команда, которая что-то меняет, в чат сразу не выполняется. Какие спрашивают, объявляет
сама команда флагом `confirm` (см. [TOOLS.md](TOOLS.md#манифест)): по умолчанию —
да, `false` — только для команд, которые смотрят или считают.

1. Модель вызывает, например, `fs.move`. agent-loop проверяет аргументы по схеме
   команды (если они неверны, ошибка возвращается сразу, без вопроса), записывает
   вызов в трейс со статусом `needs_approval` и отдаёт модели `action_id`.
2. Модель описывает пользователю действие и заканчивает ответ вопросом.
3. Пользователь отвечает. Модель вызывает `action_confirm(action_id)`, и только тогда
   вызов уходит в executor — один раз.

**Ответ должен быть ответом пользователя.** `action_confirm` срабатывает, только если
после вопроса в чате появилось сообщение пользователя. В том же ходе подтвердить
нельзя: текст, который модель прочитала (письмо, документ), не может подтвердить
действие за пользователя, сообщение задачи — тоже.

**«Да, и больше не спрашивай».** Пользователь может разрешить команду на весь чат:
модель передаёт `action_confirm(action_id, remember=true)`, и дальше эта команда в этом
чате выполняется без вопроса — с любыми аргументами. Согласие живёт в памяти
agent-loop и пропадает при его перезапуске, тогда чат просто снова спросит. Команды с
`confirm="always"` (сейчас `mail.send`) спрашивают каждый раз, что бы пользователь ни
ответил: повтор письма — ровно тот случай, когда вопрос полезен.

Действия, которые имеют смысл только после подтверждённого (пометить письмо
прочитанным после ответа на него), агент делает после `action_confirm`.

## Сообщения задач

Запуск задачи может сообщить что-то пользователю (`user.notify`, см.
[RUNS.md](RUNS.md#уведомления)). Такое сообщение приходит в чат задачи как
`«Задача «название»: текст»` и хранится с отдельной ролью `notice`:

- оно может прийти посреди хода, пока агент ждёт результатов команд. В историю для
  модели оно ставится после завершённого обмена «вызов → результаты», иначе строгие
  серверы отвергли бы историю;
- модель видит его помеченным как сообщение задачи, а не как свои слова;
- оно не считается ответом пользователя на вопрос;
- компилятор при сборке задачи его не видит.

## Мета-инструменты

Кроме команд из каталога, агент управляет самой системой. Эти инструменты живут в
`agent_loop/meta_tools.py` и идут в main, а не в executor.

| Инструмент | Что делает |
| --- | --- |
| `task_compile {title?, hint?}` | Собрать задачу из этого чата; в `hint` — расписание и пожелания. Возвращает шаги, расписание словами и настройки задачи строками вида «Отправлять письма сразу: выключено. …» |
| `task_dry_run {task_id, version_id}` | Пробный запуск версии; результат по шагам как есть, с ошибками и журналом «сделал бы …» каждого шага: модель пересказывает его как пробный, а неудачный не чинит без просьбы |
| `task_patch {task_id, instruction}` | Правка задачи словами → черновик новой версии и «было → стало» |
| `task_reject {task_id, version_id}` | Отклонить черновик |
| `task_list` | Задачи пользователя: шаги, расписание словами, настройки и черновик, который ждёт одобрения |
| `task_runs {task_id}` | Последние запуски задачи: `run_id`, когда, пробный ли, чем закончился |
| `accounts_list` | Аккаунты пользователя: имя (для аргумента `account`), вид, адрес; без паролей |
| `task_run_now {task_id}` | Запустить задачу сейчас; спрашивает «да» каждый раз |
| `task_control {task_id, action}` | `pause`, `resume` или `archive`; спрашивает «да» каждый раз |
| `run_status {run_id}` | Состояние запуска: шаги, ошибки, результат |
| `action_confirm {action_id, remember?}` | Выполнить действие, ждавшее согласия пользователя |

**Включить задачу агент не может:** инструмента для одобрения у него нет, отвечать на
одобрения он не умеет. Одобряет только сам пользователь (см.
[TASKS.md](TASKS.md#одобрение)). Настройки задачи агент тоже не меняет: он только
пересказывает их пользователю.

## Маршруты agent-loop

Снаружи доступны через main с префиксом `/agent` (см. [API.md](API.md#чат)).

| Маршрут | Что делает |
| --- | --- |
| `POST /v1/chat/completions` | Ход чата |
| `GET /v1/models` | Модель `office-agent` |
| `GET /sessions`, `GET /sessions/{id}` | Список чатов (`task_id` — у чата задачи); чат с сообщениями и трейсом |
| `GET /sessions/{id}/transcript` | Чат для компилятора: текст с вызовами и результатами (`text`), команды, которые сработали (`done_tools`), и тексты пользователя для дословного переноса (`given`) |
| `GET /meta-tools` | Мета-инструменты с названиями, которые видит пользователь |
| `DELETE /sessions/{id}` | Удалить временный чат сразу; чат задачи или чат, где агент ещё работает, — `409` |
| `POST /sessions/{id}/messages {content}` | Сообщение задачи в чат (зовёт main) |
