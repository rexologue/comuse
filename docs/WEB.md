# Фронт

Этот документ описывает веб-интерфейс в `web/`: как он подключается к агенту, как
устроен и как его запускать.

Фронт — такой же клиент внешнего API main, как curl или OpenAI-клиент: о сервисах за
main он не знает, а всё, что он умеет, умеет и API (см. [API.md](API.md)).

## Стек

Vite, React, TypeScript, Tailwind и компоненты в духе shadcn/ui (`src/components/ui`,
исходники в проекте), иконки lucide, TanStack Query для данных с сервера, React Router.
Версии зависимостей закреплены точно, `package-lock.json` в репозитории.

## Подключение к main

- **Через dev-сервер** (по умолчанию). Vite проксирует `/api/*` в main и сам подставляет
  `Authorization: Bearer <токен>`: браузер токена не видит, CORS не нужен. Адрес и токен
  dev-сервер берёт из `AGENT_API_URL` и `AGENT_TOKEN_FILE` (их задаёт dev-compose), а
  если их нет — из `data/runtime.json` (`main_url`, `token_file`); при заданном
  `API_TOKEN` — из `AGENT_API_TOKEN`. Файл токена читается на каждый запрос: main
  создаёт его при первом старте, возможно позже dev-сервера.
- **Напрямую.** Если main недоступен или отклонил токен, фронт показывает экран
  «Нет связи»: адрес main и токен из `DATA_DIR/api_token` вводятся вручную и хранятся
  только в этом браузере. Тогда адрес страницы должен быть в `ALLOWED_ORIGINS` main.

Связь проверяется запросом `GET /settings` раз в 15 секунд: он заодно проверяет токен.
Точка рядом с названием — зелёная, если агент на связи.

## Раскладка

| Где | Что |
| --- | --- |
| Сверху | Название, связь, колокольчик событий, тема (как в системе, светлая, тёмная), настройки |
| Слева | «Новый чат», задачи (по клику — чат задачи) и временные чаты |
| В центре | Чат |
| Справа | Открыта задача — её панель; иначе, или по колокольчику, — события |

**Узкие окна.** От 1280 px — три колонки. Уже — правая панель выезжает поверх чата по
кнопке панели наверху; колокольчик и открытая версия или журнал запуска выдвигают её
сами. Уже 1024 px так же выезжает и левая панель — по кнопке меню, и прячется при
переходе. Панель закрывается крестиком или кликом по затемнению. На экране настроек
правая панель — только по колокольчику.

**Ошибки.** Нет связи или отказ в токене — экран «Нет связи». Агент не отвечает (main
упал или перезапускается) — красная полоса под верхней, связь проверяется сама.
Неудачная отправка в чате показывает причину и неотправленный текст с кнопкой
«Повторить».

Тема и подключение хранятся в браузере (`localStorage`); без хранилища интерфейс
работает, просто не запоминает их.

## Чат

- **История** — `GET /agent/sessions/{id}`. Ответы агента рендерятся как Markdown (без
  сырого HTML). Сообщения задач (`notice`) оформлены отдельно, с временем. Сообщения с
  результатами команд (`tool`) не показываются: под ответом есть строки вызовов, по
  `message_id` трейса.
- **Вызовы команд** — строка на вызов: название команды из каталога (`GET /tools`) или
  мета-инструмента агента, статус (✓ выполнено, ✗ ошибка, ? ждёт ответа). По клику —
  аргументы и результат.
- **Отправка** — `POST /agent/v1/chat/completions` без стриминга. Пока агент работает,
  под сообщением идут живые строки из событий `agent.tool` этого чата. Новый чат
  (`/chat/new`) получает id из первого ответа.
- **Ход, начатый не здесь** — если в чате идёт ход, которого страница не запускала
  (другая вкладка, перезагрузка), `busy` из `GET /agent/sessions/{id}` показывает
  «Агент ещё отвечает…», чат перечитывается раз в 2 секунды до конца хода, а отправить
  новое сообщение нельзя (набрать заранее — можно).
- **Вопрос перед действием** — если в последнем ответе есть вызов `needs_approval`, а
  пользователь ещё не ответил, над полем ввода — «Да», «Да, больше не спрашивать в этом
  чате» (только для команд с `confirm: true`) и «Нет». Кнопки просто отправляют этот
  ответ сообщением: логика согласия — в agent-loop (см. [CHAT.md](CHAT.md#вопрос-перед-действием)).
- **Удалить чат** — только временный (`DELETE /agent/sessions/{id}`), с подтверждением.

## Задача

Справа, если открыт чат задачи (или `/task/{id}`), — панель задачи сверху вниз:

1. **Шапка** — название, статус, описание, расписание словами (поле `schedule`),
   следующий запуск (`GET /jobs`), кнопки «Запустить», «Пауза» / «Возобновить», «В
   архив» (с подтверждением).
2. **Настройки задачи** — построчно, как настройки сэмплинга: название, описание, справа
   значение для всей задачи; не менявшееся показано как «По умолчанию · выкл». Каждое
   изменение сохраняется сразу (`PATCH /tasks/{id}/settings`), пустое значение — снять.
3. **Шаги** — шаги активной версии, у неодобренной задачи — её последнего черновика с
   кнопками «Пробный запуск», «Одобрить», «Отклонить». Клик по шагу раскрывает его:
   команда, аргументы и внизу настройки этого шага («Как для задачи · вкл» или своё
   значение). Если команды задачи изменились после одобрения, плашка говорит, какие и что
   в них («`demo.count` — код, аргументы»), и кнопка «Посмотреть задачу с новыми
   командами» (`POST /tasks/{id}/tools/refresh`) открывает черновик на месте.
4. **Версии** — номер, что изменилось, статус («активная», «черновик», «заменена»,
   «отклонена»). Клик открывает версию: когда и как создана, diff «было → стало»
   (`GET /tasks/{id}/versions/{v}/diff`), сценарий, у черновика — его кнопки.
5. **Запуски** — цвет: зелёный — успешно, красный — ошибка, серый — отменён или нечего
   делать, синий — идёт; пустые проверки — по флажку. Клик открывает журнал запуска.

Версия и запуск открываются на месте панели и попадают в адрес (`?version=`, `?run=`),
стрелка возвращает к задаче. **Журнал запуска** (`GET /runs/{id}` и `/log`): как и
когда запущен, сколько длился, ошибка, записи начала, шагов (каждая попытка: команда,
аргументы, результат, строки команды, ошибка, traceback), сообщений пользователю и
конца. Запуск, который ещё идёт, обновляется раз в полторы секунды, его можно отменить.

**Черновик в чате.** Под перепиской — карточка каждого черновика этого чата, который ждёт
решения (`GET /approvals?session_id=`): название, расписание, шаги, «Пробный запуск»
(журнал открывается справа), «Одобрить», «Отклонить» и «Изменить словами»
(`POST /compiler/patch`) — после правки карточка показывает, что изменилось. Одобрить
может только пользователь: у агента такого инструмента нет.

**Черновик плагина в чате.** Если агент написал в этом чате свою команду (`tools.draft`),
под перепиской — карточка черновика её плагина: команды, точные пакеты, код
(раскрывается), «Одобрить» и «Выбросить».

## Лента событий

Справа, когда задача не открыта, — лента; колокольчик наверху открывает её поверх задачи.

- **Ждут решения** — черновики, ждущие одобрения (`GET /approvals`); клик открывает их
  чат.
- **Идут сейчас** — запуски, у которых в загруженных событиях есть `run.started`, но
  нет `run.finished`; с кнопкой отмены.
- **Лента** — события от новых к старым: сообщения задач (с текстом), начало и конец
  запусков (зелёный — успешно, красный — ошибка с её текстом), черновики, одобрения,
  пауза и архив задач. `agent.tool` в ленту не попадает: это прогресс чата. Клик ведёт в
  чат задачи, а у запуска — сразу в его журнал. Название задачи, которой уже нет в
  списке (архивной), берётся из других её событий.
- **Непрочитанные** — число на колокольчике: события новее последнего увиденного. Что
  увидено, помнит браузер (`localStorage`), на сервере чтение не хранится; при первом
  входе всё, что уже было, считается прочитанным. Открытая лента читает всё сразу.

Последние 200 событий загружаются из `GET /events/recent`, новые дописываются из потока
без повторного запроса.

## Настройки

Шестерёнка наверху, `/settings/<вкладка>`; правая панель здесь только по колокольчику.

- **Модели** (`/llm`, см. [LLM.md](LLM.md)) — роли «Чат», «Инструкции», «Эмбеддинги»:
  выбор провайдера и «Назначить», ошибка проверки показывается под ролью. Провайдеры —
  с ролями, кнопками «Проверить как чат» и «Как эмбеддинги», правкой (новый ключ или
  «Убрать ключ») и удалением. Мастер «Добавить провайдера»: адрес и ключ → «Получить
  список моделей» (`POST /llm/models`) → модель → название.
- **Рабочие** (`/settings`, см. [SETTINGS.md](SETTINGS.md)) — поле по типу настройки;
  заданные окружением заблокированы с пометкой, изменённые — с кнопкой «По умолчанию».
- **Аккаунты** (`/accounts`) — форма строится из полей вида (`GET /accounts/kinds`):
  интерфейс ничего не знает о почте. Пресет провайдера подставляет значения подсказками,
  уходит только то, что ввёл пользователь. Проверка входа и удаление.
- **Плагины** (`/plugins`, `/tools`, см. [PLUGINS.md](PLUGINS.md)) — плагины: одобренный
  код и черновик (кто написал — вы или чат), работает ли сервер и почему нет, команды,
  пакеты, файлы; «Проверить запуск», «Одобрить» и «Выбросить» у черновика, «Править
  черновик» / «Черновик на основе этого кода», «Перезапустить», «Удалить плагин» и
  «Добавить плагин» — форма с `plugin.json`, файлами и пакетами. Ниже — встроенные
  команды по группам, только для чтения.
- **О программе** — как подключён интерфейс, сервисы и когда они отмечались, хвост логов
  (`GET /logs`) с выбором файла и числа строк.

**Первый запуск.** Пока на роль «Чат» ничего не назначено, под верхней полосой —
«Модель для чата не подключена» со ссылкой на «Модели».

## События

Одно SSE-подключение к `GET /events` на всё приложение (`src/api/events.tsx`). После
обрыва оно переподключается с `since` — последним увиденным id, поэтому события не
теряются. Каждое событие обновляет данные, которые оно меняет: `approval.*` и `task.*` —
задачи, чаты, одобрения и расписание, `run.*` — задачи и запуски, `notify` — открытые
чаты (так сообщение запуска появляется в чате задачи само). Экраны, которым нужны сами
события (живой прогресс чата, лента), подписываются через `useEvents`.

## Код

```text
web/
  vite.config.ts       dev-сервер и прокси /api с токеном
  src/
    api/               подключение, клиент, типы ответов, запросы TanStack Query, поток событий
    app/               раскладка: верхняя полоса, панели, экран подключения
    chat/              чат: лента, вызовы команд, вопросы, черновики, поле ввода
    task/              панель задачи: сценарий, версии и diff, настройки, запуски и журнал
    events/            лента событий, непрочитанные
    settings/          настройки: модели, рабочие, аккаунты, команды, о программе
    pages/             остальное содержимое центра
    components/ui/     базовые компоненты
    theme.tsx          светлая и тёмная тема
    lib/               форматирование, ширина окна, мелочи
```

## Запуск

Node ставится только в Docker: фронт работает в контейнере `web` dev-compose рядом с
агентом (см. [DEPLOY.md](DEPLOY.md#docker-для-разработки)):

```bash
docker compose -f deploy/compose.dev.yaml up --build
```

Интерфейс — `http://localhost:5173` (`AGENT_DEV_WEB_PORT`). `web/` примонтирована,
правки видны сразу; `node_modules` ставятся в `web/` от имени вашего пользователя.
Команды npm — в том же контейнере:

```bash
docker compose -f deploy/compose.dev.yaml run --rm --no-deps web npm run build
```

`npm run build` проверяет типы и собирает статику в `web/dist`: библиотеки — отдельными
кусками (react, данные, markdown, интерфейс), экран настроек грузится, когда его
открывают, `npm test` — тесты
vitest. Как отдавать собранную статику без dev-сервера, решится вместе с приложением
Tauri.
