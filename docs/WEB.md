# Фронт

Этот документ описывает веб-интерфейс в `web/`: как он подключается к агенту, как
устроен и как его запускать.

Фронт — такой же клиент внешнего API main, как curl или OpenAI-клиент: о сервисах за
main он не знает, а всё, что он умеет, умеет и API (см. [API.md](API.md)).

## Стек

Vite, React, TypeScript, Tailwind и компоненты в духе shadcn/ui (`src/components/ui`,
исходники в проекте), иконки lucide, TanStack Query для данных с сервера, React Router.
Версии зависимостей закреплены точно, `package-lock.json` в репозитории.

## Подключение к main

- **Через dev-сервер** (по умолчанию). Vite проксирует `/api/*` в main и сам подставляет
  `Authorization: Bearer <токен>`: браузер токена не видит, CORS не нужен. Адрес и токен
  dev-сервер берёт из `AGENT_API_URL` и `AGENT_TOKEN_FILE` (их задаёт dev-compose), а
  если их нет — из `data/runtime.json` (`main_url`, `token_file`); при заданном
  `API_TOKEN` — из `AGENT_API_TOKEN`. Файл токена читается на каждый запрос: main
  создаёт его при первом старте, возможно позже dev-сервера.
- **Напрямую.** Если main недоступен или отклонил токен, фронт показывает экран
  «Нет связи»: адрес main и токен из `DATA_DIR/api_token` вводятся вручную и хранятся
  только в этом браузере. Тогда адрес страницы должен быть в `ALLOWED_ORIGINS` main.

Связь проверяется запросом `GET /settings` раз в 15 секунд: он заодно проверяет токен.
Точка рядом с названием — зелёная, если агент на связи.

## Раскладка

| Где | Что |
| --- | --- |
| Сверху | Название, связь, колокольчик событий, тема (как в системе, светлая, тёмная), настройки |
| Слева | «Новый чат», задачи (по клику — чат задачи) и временные чаты |
| В центре | Чат |
| Справа | Открыта задача — её панель; иначе, или по колокольчику, — события |

Тема и подключение хранятся в браузере (`localStorage`); без хранилища интерфейс
работает, просто не запоминает их.

## Код

```text
web/
  vite.config.ts       dev-сервер и прокси /api с токеном
  src/
    api/               подключение, клиент, типы ответов, запросы TanStack Query
    app/               раскладка: верхняя полоса, панели, экран подключения
    pages/             содержимое центра по маршрутам
    components/ui/     базовые компоненты
    theme.tsx          светлая и тёмная тема
```

## Запуск

Node ставится только в Docker: фронт работает в контейнере `web` dev-compose рядом с
агентом (см. [DEPLOY.md](DEPLOY.md#docker-для-разработки)):

```bash
docker compose -f deploy/compose.dev.yaml up --build
```

Интерфейс — `http://localhost:5173` (`AGENT_DEV_WEB_PORT`). `web/` примонтирована,
правки видны сразу; `node_modules` ставятся в `web/` от имени вашего пользователя.
Команды npm — в том же контейнере:

```bash
docker compose -f deploy/compose.dev.yaml run --rm --no-deps web npm run build
```

`npm run build` проверяет типы и собирает статику в `web/dist`, `npm test` — тесты
vitest. Как отдавать собранную статику без dev-сервера, решится вместе с приложением
Tauri.
