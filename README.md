# fintech2026 · офисный агент

Пользователь объясняет задачу в обычном чате («вот пример отчёта, сделай такой же за прошлую
неделю»). Агент делает её через инструменты, а по команде «делай так каждый понедельник»
компилирует разговор в замороженный сценарий (Task). Дальше сценарий исполняется по расписанию
без LLM-планирования: шаг за шагом, с правами, подтверждениями и историей запусков.

Полное ТЗ: [docs/SPEC.md](docs/SPEC.md).

## Сервисы

Шесть FastAPI-сервисов. Каждый — отдельный процесс, все вызовы между ними идут через `main`.

| Сервис | Порт | Что делает |
|---|---|---|
| `main` | 8000 | Шлюз, реестр сервисов, подтверждения, события (SSE), токены |
| `agent_loop` | 8001 | Чат в формате OpenAI, цикл «LLM → инструменты», трейс |
| `compiler` | 8002 | Чат → Task, проверка, права, карточки, правки через JSON Patch, пробный запуск |
| `runner` | 8003 | Исполнение Task по шагам; пауза на подтверждение и продолжение |
| `executor` | 8004 | Единственное место, где выполняются команды: права, секреты, аудит |
| `scheduler` | 8005 | Cron, новые файлы в папке, новые письма |

Команды лежат в `internal_tools/`: одна команда (или пара с общим входом) — один файл с `@tool`.

## Быстрый старт (Windows, Linux, macOS)

```bash
uv sync --extra dev
```

```bash
cp .env.example .env
```

```bash
uv run python misc/make_demo_data.py workspace
```

```bash
uv run python launcher.py
```

API: `http://127.0.0.1:8000`, документация — `http://127.0.0.1:8000/docs`.
`python launcher.py runner` поднимает один сервис, `--reload` перезапускает его при правке кода.

Первое сообщение в чат:

```bash
curl -s -X POST localhost:8000/agent/v1/chat/completions -H 'content-type: application/json' -d '{"messages":[{"role":"user","content":"В папке Отчёты/Пример лежит пример еженедельного отчёта. Сделай такой же отчёт за прошлую неделю по выгрузкам из папки Отчёты/Продажи."}]}'
```

Ответ содержит `session_id`. Следующие сообщения передавайте с `"metadata": {"session_id": "…"}`.

## LLM

Подходит любой OpenAI-совместимый `/v1` с вызовом инструментов. Модели задаются только в конфиге:

| Переменная | Зачем |
|---|---|
| `LLM_MODEL` | Одна модель на всё (обязательна) |
| `LLM_MODEL_CHAT` | Переопределение: агент в чате и компиляция задач (многошаговые) |
| `LLM_MODEL_INSTRUCT` | Переопределение: `llm.*`-команды и разметка шаблонов (одиночные вызовы) |
| `LLM_CHAT_REASONING_EFFORT` | `low` / `medium` / `high` для reasoning-моделей; пусто — не отправляется |
| `LLM_MODEL_EMBED` | Отбор инструментов по смыслу; пусто — агент видит все |

Structured output необязателен: клиент перебирает `json_schema` → `json_object` → обычный текст
со схемой в промпте и запоминает, что сработало для модели.

Остальные переменные описаны в [.env.example](.env.example).

## Docker

```bash
cp deploy/.env.example deploy/.env
```

```bash
docker compose -f deploy/docker-compose.yaml up -d --build
```

Один образ, по контейнеру на сервис. Наружу открыт только `main`. Данные лежат в томе `agent-data`,
папка пользователя монтируется в `/workspace` (`AGENT_DEPLOY_WORKSPACE_PATH`).

## Основные эндпоинты

| Путь | Что делает |
|---|---|
| `POST /agent/v1/chat/completions` | Чат |
| `GET /tasks`, `GET /tasks/{id}` | Задачи и их шаги |
| `POST /tasks/{id}/versions/{v}/approve` | Включить версию задачи |
| `POST /runs` | Запустить задачу сейчас |
| `GET /runs/{id}` | Ход запуска по шагам |
| `GET /approvals`, `POST /approvals/{id}/answer` | Вопросы и подтверждения |
| `GET /events` | Поток событий (SSE) |
| `POST /accounts` | Почтовый аккаунт (пароль уходит в keyring) |
